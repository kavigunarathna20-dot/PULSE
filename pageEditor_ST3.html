Feedback

Technical Description

This page was developed using HTML5, CSS3, and JavaScript to create an interactive and responsive user experience. Semantic HTML elements such as header, nav, main, section, footer, form, fieldset, and legend were used to improve the document structure and readability.

CSS Grid and Flexbox were used to create responsive layouts for the program cards, review cards, and form controls. Media queries adapt the layout for tablets and mobile devices by adjusting grid columns, spacing, and typography. Interactive styling, including hover effects, focus indicators, transitions, and animations, enhances the user experience.

JavaScript adds functionality including live character counting, real-time form validation, success messages, and a sorting dropdown for the program listings.

Accessibility

The page follows basic accessibility practices by using descriptive alt text for images, properly associated form labels, and semantic HTML elements. Keyboard users can navigate interactive elements using visible focus indicators, while clear validation and error messages assist users when completing the feedback form.The responsive design, readable typography, and consistent navigation help ensure the page is accessible and usable across desktop, tablet, and mobile devices.

Team

Technical Description

This webpage was developed using HTML5, CSS3, and JavaScript to create a responsive and interactive team page. Semantic HTML elements such as header, nav, main, section, and footer were used to organize the content and improve the overall page structure. CSS Grid and Flexbox were implemented to create a responsive two-column layout that automatically adjusts for smaller screens using media queries. Interactive features, including hover effects, transitions, and expandable team member cards, provide an engaging user experience.

JavaScript was used to enhance functionality by enabling keyboard interaction, allowing users to expand team member cards using the Enter or Space keys. This improves usability while ensuring the page remains interactive and accessible across different devices and input methods.

Accessibility

The page follows accessibility best practices by using descriptive alt text for images, semantic HTML elements, and keyboard-focusable team member cards. Visible focus indicators and keyboard support ensure users can navigate and interact with the page without relying on a mouse.

The responsive design, clear typography, and consistent navigation make the page accessible and easy to use across desktop, tablet, and mobile devices.

Challenges & Lessons Learned

Dual Form Validation

Form validation only worked on submit, not during typing. Users didn't know about errors until final submission.

Solution: Added blur event listeners for real-time field validation, plus submit event validation for final check. Errors clear as soon as user corrects them.

Lesson Learned: Real-time feedback during form filling improves UX. Blur + submit approach catches errors early while ensuring final safety check.

Character Counter Color Logic

Counter needed color changes at thresholds (gray → orange at 400 → red at 450), but boundary values caused incorrect colors.

Solution: Ordered if-else conditions checking highest threshold first : >450 red, >400 orange, else gray. Added input event listener for paste/cut operations.

Lesson Learned: Conditional logic order matters. Use input event for real-time character tracking, not just change. Color feedback builds user trust in limits.

Team Card Details Overlapping

Expandable details were clipped by overflow: hidden and overlapped neighboring cards.

Solution: Changed overflow: visible, used position: absolute; top: 100% for details, added z-index: 10 to float above cards.

Lesson Learned: overflow: hidden clips absolutely positioned elements. Understanding overflow + position + z-index is crucial for layered UI.

Keyboard Accessibility Focus

tabindex="0" made cards focusable but keyboard focus didn't trigger expand effect - felt unresponsive.

Solution: Added :focus-within CSS selector to expand on focus. Combined with keyboard event listener for Enter/Space.

Lesson Learned: :focus-within triggers when element or children have focus. CSS selectors handle interaction better than complex JavaScript for accessibility.
