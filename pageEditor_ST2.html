Splash Screen

Technical Description

The Splash Screen was developed using HTML5, CSS3, and JavaScript to create an animated introductory page. Semantic HTML elements such as header, main, section, and footer structure the page, while CSS animations (keyframes for fade-in and slide-up effects) create a visually engaging loading experience. A JavaScript timer automatically redirects to the home page after 4 seconds, providing a smooth transition into the website. The page includes team member information, the PULSE logo, and the SDG 3 tagline displayed with animated typography.

Accessibility

The Splash Screen was designed with accessibility in mind by using descriptive alt text for all images, sufficient colour contrast between text and background, and a clear heading structure. The auto-redirect includes a visible countdown indicator, giving users awareness of the transition timing. Semantic HTML elements ensure screen readers can properly interpret the page structure, and the responsive design ensures legibility across devices.

Action Impact Simulator

Technical Description

The Action Impact Simulator was built using HTML5, CSS3, and JavaScript to create an interactive wellness tool. Semantic HTML elements such as header, nav, main, section, and footer provide the page structure. CSS Grid and Flexbox lay out the action cards, impact score display, and selected actions panel in a responsive design. JavaScript manages the core interactivity: each action card has a point value and category, and selecting/deselecting actions updates a running wellness score in real time. Dynamic background images change based on the user's total score (low/medium/high impact) using CSS class toggling on the <body> element, providing visual feedback for progress.

Accessibility

The Action Impact Simulator was designed with accessibility in mind by using descriptive alt text for images, keyboard-focusable action cards, and clear visual feedback for selected states. Action cards are implemented as native <button> elements, ensuring keyboard users can tab through and activate them without custom key handlers. The wellness score and selected actions panel update dynamically with clear text announcements, and colour-coded impact levels (low/medium/high) are supplemented by text labels rather than relying solely on colour. Sufficient colour contrast and responsive typography improve readability across devices.

Physical Activity & Exercise

Technical Description

The Content Page was developed using HTML5 and CSS3, with an emphasis on structured long-form content about physical activity and exercise. Semantic HTML elements such as header, nav, main, section, and footer organise the page, and heading levels follow a strict hierarchy with each major topic beginning at <h2> and subheadings using <h3>. CSS Grid and Flexbox create responsive layouts for information cards, article sections, and resource links. An in-page navigation menu provides jump links to each section using anchor targets, and a fixed-position "Go to Top" link remains visible throughout the page using pure CSS.

Accessibility

Accessibility on the Content Page was addressed primarily through heading structure: heading levels are used consistently and in order, so the page outline remains meaningful to screen reader users navigating by heading. Every image includes descriptive alt text specific to its content. The in-page navigation menu and "Go to Top" link are implemented as native <a> elements, making them keyboard-focusable by default. scroll-margin-top ensures anchor-link jumps don't land content behind the sticky header. The responsive layout and readable typography ensure the page is accessible across devices.

Challenges & Lessons Learned

Background Image Overlay Conflict

The AIS page's body background images were not showing because a ::before pseudo-element on <body> in the shared CSS was painting a white layer on top of the actual background image.

Solution: Added page-specific CSS rules that set background-color: transparent !important on the ::before pseudo-element when the AIS page's body class is present, allowing the background image to show through.

Lesson Learned: Shared CSS pseudo-elements can unintentionally override page-specific styling. Using scoped class selectors prevents global styles from breaking individual pages.

Trailing Slash Validation Errors

All HTML files had trailing slashes on void elements (<meta />, <img />, <br />) which triggered W3C validation info messages across every page.

Solution: Used a PowerShell regex replacement to remove all trailing slashes from void elements across all 23 HTML files at once, resolving hundreds of validation info messages.

Lesson Learned: In HTML5, void elements don't need self-closing slashes. Bulk regex replacements must be carefully tested, as an incorrect regex can corrupt tag names and break all pages.

Splash Screen Timer Timing

The auto-redirect on the splash page needed to give users enough time to read the content while not feeling too slow. Initial attempts either redirected too quickly or lingered too long.

Solution: Set a 4-second setTimeout with a visible animated progress bar and countdown indicator, giving users clear awareness of the timing without making them wait unnecessarily.

Lesson Learned: User perception of loading time matters as much as the actual duration. Visual progress indicators improve the perceived experience of timed transitions.

Compliance

All content across the Splash Screen, Action Impact Simulator, and Content pages is original and truthful, with no material copied from external sources such as the UN SDG website. Action descriptions, impact calculations, and physical activity content are written specifically for this project. No misleading or inappropriate content has been included.

All images are sourced from royalty-free platforms, with appropriate alt text included for accessibility. No copyrighted or trademarked material has been used. External articles linked from the Content Page point to their original sources (WHO, NHS, CDC) and are clearly marked as external links.

All HTML, CSS, and JavaScript across these three pages was written without plagiarism or uncredited code copying. Each footer correctly attributes the work to Student 2.

None of these pages collect or store user data — no forms, cookies, analytics, or external data transmission are implemented. The AIS page uses only client-side JavaScript with no data sent to any server.

All three pages use valid HTML5 compliant with W3C standards, are responsive across screen sizes, and have been tested across major browsers including Chrome, Safari, and Edge. This satisfies JANET regulations for responsible web publishing at UK educational institutions.
