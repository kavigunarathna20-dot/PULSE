Home Page

Technical Description

The Home page was developed using HTML5, CSS3, and JavaScript to create an interactive, scroll-reveal driven landing experience. Semantic HTML elements such as header, nav, main, section, and footer structure the page, with the hero area (heading, subtitle, and call-to-action link), the "Mission and Goals" section, and the "Explore Our Content Pages" section organised as separate <section> elements inside <main>. CSS Grid lays out the three mission cards and four content boxes responsively, while a small JavaScript reveal() function checks each element against getBoundingClientRect() on every scroll event, adding an active class that triggers a fade-and-slide-in transition as the user scrolls.

Accessibility

Accessibility on the Home page was addressed by giving every image — including the main logo, the three mission-card images, and the four content-page thumbnails — descriptive alt text, and by using a single <h1> for the page's main heading followed by <h2> elements for each section title, so screen reader users can navigate the page by heading level. Interactive elements such as the "Explore More" call-to-action and each content-box link are implemented as native <a> elements rather than clickable <div>s, ensuring they are reachable and operable via keyboard by default.

Gallery

Technical Description

The Gallery page was developed using HTML5, CSS3, and JavaScript to create an interactive, filterable image gallery with a fully custom modal. Semantic HTML elements such as header, nav, main, and footer provide the page's overall structure, while the gallery itself is built from repeatable card elements inside a CSS Grid container, each carrying data-category, data-title, data-desc, and data-img attributes that JavaScript reads to drive its behaviour. Category filtering compares each card's dataset against the selected filter button, and a single reusable modal is populated dynamically from whichever card was clicked, keeping the DOM lightweight rather than duplicating a modal per image. The modal also includes button-based theme and font customisation, implemented by toggling CSS classes and inline font-family styles.

Accessibility

Accessibility on the Gallery page was addressed by giving every thumbnail and modal image descriptive alt text drawn from each item's title, and by implementing the modal's close control as a real <button> element rather than a styled <div>, so it is reachable and operable via keyboard and announced correctly by screen readers. Category filter buttons and the theme/font customisation controls are also built as native <button> elements, giving them built-in keyboard focus and activation support without any custom key-handling code. Clicking outside the modal content area closes it, giving keyboard and mouse users an additional way to dismiss the popup.

Mental Health & Well-Being

Technical Description

The Content Page was developed using HTML5 and CSS3, with an emphasis on structured, accessible long-form content. Semantic HTML elements such as header, nav, main, section, and footer organise the page, and heading levels follow a strict hierarchy, with each major topic beginning at <h2> and card or content-block subheadings using <h3>. An in-page navigation menu provides jump links to each section using anchor targets matched to section id attributes, paired with a scroll-margin-top rule so jumping to a section doesn't hide it behind the sticky header. A fixed-position "Go to Top" link remains visible throughout the page using pure CSS, requiring no JavaScript.

Accessibility

Accessibility on the Content Page was addressed primarily through structure: heading levels are used consistently and in order rather than being chosen for visual size, so the page's outline remains meaningful to screen reader users navigating by heading. Every image across the page includes descriptive alt text specific to its content, rather than generic placeholders. The in-page navigation menu and "Go to Top" link are both implemented as ordinary <a> elements, meaning they are keyboard-focusable by default, and scroll-margin-top ensures anchor-link jumps don't land content behind the sticky header.

Challenges & Lessons Learned

Duplicated Shared Template Code

Every page carried its own copy of the shared header, nav, and footer, since there were no server-side includes keeping them identical across pages was easy to get wrong.

Solution: Treated template.html as the single source of truth and copied directly from it for every new page, rather than editing an existing page's copy.

Lesson Learned: Static HTML without includes needs stricter manual discipline than a framework would enforce automatically.

Duplicate Modal IDs

An early Gallery version used a separate modal for every image, all sharing the same id , so only the first was ever addressable, and all four stayed visible permanently.

Solution: Refactored to one reusable modal populated dynamically via data-* attributes, with visibility controlled by a JavaScript-toggled active class.

Lesson Learned: Interactive components need to be clicked through and tested early duplicate IDs and always-visible overlays are easy to miss otherwise.

Inconsistent Class Naming

Class naming drifted across pages, Home used .card, Gallery used .gallery-card making the code harder to read consistently.

Solution: Prefixed page-specific classes clearly and added a comment block at the top of each <style> explaining its structure.

Lesson Learned: Agreeing on naming conventions before development starts saves time versus reconciling them afterward.

Compliance

All content across the Home, Gallery, and Content pages is original and truthful, with no material copied from external sources such as the UN SDG website. Card descriptions, gallery captions, and the mental health content are written specifically for this project. No misleading or inappropriate content has been included.

All images are sourced from royalty-free platforms such as iStockPhoto, with appropriate alt text included for accessibility. No copyrighted or trademarked material has been used. A small number of article thumbnails on the Content Page still link directly to Unsplash and will be downloaded into the local images folder before submission.

All HTML, CSS, and JavaScript across these three pages was written without plagiarism or uncredited code copying. Each footer correctly attributes the work to Student 1. External articles linked from the Content Page point to their original sources (WHO, NIH, NCCIH) and are clearly marked as external links.

None of these pages collect or store user data no forms, cookies, analytics, or external data transmission are implemented. All interactivity (filtering, modal display, scroll-reveal, theme/font customisation) runs client-side only.

All three pages use valid HTML5 compliant with W3C standards, are responsive across screen sizes, and have been tested across major browsers including Chrome, Safari, and Edge. This satisfies JANET regulations for responsible web publishing at UK educational institutions.
